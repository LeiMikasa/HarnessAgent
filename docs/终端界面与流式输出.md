# 终端界面与流式输出

## 启动

```powershell
cd D:\HarnessAgent
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m agent --tui --workdir "D:\btest"
```

界面是终端应用，推荐使用 Windows Terminal / PowerShell 窗口。增加 `--teams` 开启后台队友，增加 `--full` 同时开启团队和长期记忆。原来的普通 CLI 和单次任务输出方式继续保留；只有显式使用 `--tui` 才进入新界面并启用用户回答的流式显示。`--quiet` 与 `--tui` 不能同时使用。

免费演示（会在指定的临时工作区创建 greeting.py）：

```powershell
.\.venv\Scripts\python.exe -m agent --tui --mock --demo --workdir .scratch\tui-demo
```

## 使用

- Enter 发送；Alt+Enter、Shift+Enter 或 Ctrl+J 换行。不同终端对组合键支持不同，Ctrl+J 可作为换行备选。
- Ctrl+P / Ctrl+N 浏览当前会话的输入历史；Ctrl+L 回到输入框。
- Ctrl+T 在暖灰深色主题与浅色主题之间切换；切换不清空输入或对话。
- Ctrl+C 请求停止当前任务；空闲时清空输入。Ctrl+Q 或 `:quit` 退出。
- 点击工具卡片展开参数与输出；错误卡片自动展开。`--verbose` 让工具卡片默认展开，不直接向终端交错打印日志。
- 右侧显示会话统计和后台队友状态；窄于 100 列时自动隐藏侧栏。
- 右下角显示主 Agent 最近请求的上下文估计：已用、压缩预算、剩余及占用百分比；窄窗口收起侧栏时，在输入框附近显示简洁提示。
- 权限确认会打开弹窗，显示调用者、工具、理由与参数；Y 允许本次，N / Escape 拒绝。默认聚焦拒绝。已有 allow/deny 配置继续生效。
- `:status`、`:tools`、`:todos`、`:tasks`、`:team`、`:skills`、`:memory`、`:mcp`、`:notes`、`:trace`、`:help` 是本地命令，不发模型请求。`:goal <条件>` 会执行任务并可能产生模型用量。

输入在任务执行时可以编辑，但不会并行提交第二个主任务。发送消息后自动滚到底部，并跟随后续输出。
若用户向上滚动查看旧消息，暂停跟随；回到底部或再次发送消息后恢复跟随。

## 界面布局与主题

顶栏显示模型、工作区和执行状态；主区域使用连续对话布局，用户消息、模型回答及工具卡片按层级区分。欢迎提示在首次提交后移除。工具运行中显示省略号和状态色，成功后显示勾选与耗时，失败卡片显示叉号并自动展开，状态不只依赖颜色。

右侧按会话统计、执行环境和后台队友分组，显示 token、工具环境及审批策略。窗口窄于 100 列时隐藏侧栏，少于 30 行时缩小顶栏和输入区。建议使用至少 80 列 × 24 行；低于 60 列 × 18 行时显示尺寸提示，Ctrl+Q 仍可退出。

上下文栏固定在右下角，与输入区并排，不随右侧统计列表滚动；窄窗口使用输入框附近的简洁提示。它在每轮主 Agent 模型请求前、压缩处理后更新，包含系统提示词、历史消息和工具定义，估计值已包含 20% 余量。默认压缩预算为 200,000 个估计 token；“剩余”是距压缩阈值的空间，不是服务商模型容量。它显示最近请求的输入快照，不随当前响应的流式片段增长；下一次请求前重新统计。后台队友的独立上下文不会覆盖主 Agent 的数值。

右下角按来源显示分项，全部为估计 token，已包含 20% 余量，分项相加等于“已用”：

| 分项 | 包含内容 |
|---|---|
| 提示词 | 系统规则、环境、当前计划、技能目录和注入的记忆等系统提示词内容 |
| 工具定义 | 本次提供给模型的工具名称、说明和参数 Schema，未调用也占输入 |
| 工具结果 | 历史消息中的 `tool_result` 块，包含返回内容及该块自身的结构字段 |
| 对话消息 | 其余消息内容、角色及消息结构，包含用户/助手文本、思考块和工具调用参数；不重复包含工具结果块 |
| 请求结构 | 最外层请求字段、分隔符等剩余 JSON 结构字符；空的系统提示词/工具列表也归入这里 |

计数依据实际发送的序列化文本；各分项有自己的结构字段，不是只统计正文。整数舍入在分项间分配，不会因逐项向上取整而增大总量。压缩后的预览、指针和摘要按当前请求实际保留内容统计，磁盘归档正文不会额外计入。窄窗口保留总览，完整明细在宽屏右下角显示。

超过预算时剩余显示为 0，并以文字提示超出量；关闭自动压缩时只显示估计输入量，不显示剩余和占用比例。首次请求前及 `:clear` 后显示等待状态。右侧“会话累计”的输入、输出 token 仍来自接口 `usage`，不会拿估计值填充真实用量。

样式集中在 `agent/tui.tcss`，使用 Textual 主题变量；深浅主题在 `agent/tui.py` 注册。字体由终端设置决定，推荐支持中文的等宽字体。`NO_COLOR`、低颜色终端和非交互模式仍交由 Textual 与普通 CLI 的现有路径处理；跨终端的颜色和字符宽度可能不同。

## 实现

`agent/tui.py` 使用 Textual 管理界面。模型和工具运行在工作线程；通过线程安全队列发送 `UIEvent`，由 UI 线程统一更新消息、工具卡片和状态。
主 Agent、一次性子 Agent、后台队友的事件带有各自的 owner 与独立调用编号，文本片段不会混入同一个回答块。
UI 事件与调度用的 on_event、磁盘诊断日志分开，不改变队友根据工具活动判断进度的逻辑。

Loop 的 `context_usage` 事件只携带输入估计、`estimated_input_token_breakdown` 数字分项、压缩预算和估算器版本，TUI 接收主 Agent 的事件后计算显示比例。诊断事件 `context_prepared` 也保存相同分项，便于对照日志。它不在 UI 线程读取或重新估算工作线程正在修改的消息，也不重新构建系统提示词或触发记忆选择。

`agent/llm.py` 在传入文字回调时使用 SDK 的消息流，边接收公开 text_delta 边发送显示事件。
不显示 thinking、工具 JSON 片段、摘要或记忆调用的内容。完整结束后仍返回原来的 LLMResponse；供应商最终 usage 只汇总一次，不按文字片段重复累计。

工具执行仍等待整条响应完成。缺少 message_stop 的断流会报错，不接受快照中的工具调用；max_tokens 截断仍走原有丢弃和有限恢复逻辑。
界面上已经显示的部分文字会标记为未完成。流式不自动重放中断请求，避免重复输出或额外用量。

原生和 Mock 客户端支持文字流；未声明该能力的自定义 LLM 客户端继续返回完整响应，由界面一次显示。

## 停止与输出边界

停止是协作式的：收到 Ctrl+C 后拒绝待处理的权限确认，跳过尚未执行的工具，在后续流事件或循环边界检查停止标记。
已经执行的修改不会回滚；正在阻塞的网络读取或命令可能需要先返回。不会把仍在运行的工作线程误显示成可以立刻启动第二个任务。
取消时，一批工具中未执行的调用会补齐 CANCELLED 结果，保留对话工具调用/结果的配对。

工具在界面中最多预览 8000 字符，并显示实际返回长度；这不改变工具返回给模型的原始内容。
模型的后续上下文仍受已有工具输出预算与压缩规则约束。bash 自身仍在命令结束后返回结果，不是命令 stdout 的实时流。

Windows 下，工具子进程使用 `CREATE_NO_WINDOW`，避免 `cmd.exe` 重新打开 TUI 控制台的输入回显；仅捕获 stdout/stderr 并不能隔离控制台。未显式提供输入时，宿主命令及 Docker 客户端的 stdin 指向 `DEVNULL`；Docker 文件工具通过独立管道传入的 JSON 请求仍保留。权限确认仍由界面弹窗处理，不依赖工具进程读取键盘。

若旧进程中出现整屏 `^[[<35;…M`，那是鼠标事件被回显，不是中文编码问题。修复后需退出旧 Agent 并重新启动；这里保持 TUI 的鼠标操作功能，不通过删除工具输出中的文字来掩盖问题。

不把 UI 文本片段写入 runs，也不把界面事件加入模型对话。已有转录、记忆、诊断规则继续按各自配置执行。

## 离线验证

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_streaming.py -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_tui.py -v
```

SSE 假事件测试覆盖断流、完整工具参数、截断恢复、取消和 token 汇总；无头 UI 测试覆盖输入、历史、展开、审批、线程消息、深浅主题、窗口缩放以及包含中文、emoji、组合字符和阿拉伯语的输入草稿保留。Textual 不提供完整的应用层 BiDi 布局，阿拉伯语的视觉呈现仍依赖终端；文本保留测试不代表所有终端渲染一致。不需要模型 API 密钥，也不验证真实供应商的网络连通性。
