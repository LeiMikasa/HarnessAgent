# Web 工作台设计与接入

## 技术与模块

- `web/`：Vue 3、TypeScript、Vite，包含会话导航、聊天、工具卡片、任务与 token 状态、新建会话及审批弹窗。
- `agent/web/app.py`：FastAPI 路由、本机 Host/Origin 限制、静态页面与 SSE。
- `agent/web/sessions.py`：每会话独立 Runtime、后台执行线程、审批回调、运行事件投影、本地存储。
- `python -m minicode.web`：只监听本机的启动入口，默认端口 8765。

## 一次任务的流程

1. 网页新建会话，将工作目录、权限模式、是否使用 Mock 提交到 `POST /api/sessions`。
2. 后端保存会话元信息。此时不调用模型、不启动容器。
3. 网页打开 `GET /api/sessions/{id}/events`，先接收完整快照，再接收增量事件。
4. 用户发送任务到 `POST /api/sessions/{id}/messages`。会话标记为忙，后台线程创建或复用 Runtime 并调用 `runtime.submit()`。
5. 运行时沿用现有 `UIEvent`：模型开始、文本增量、模型结束、工具开始/结束、上下文估计。
6. Web 适配层把事件转成可重放的消息/工具记录，通过 SSE 推送；页面按记录 ID 更新，避免把最终回答重复追加。
7. 回合结束保存原始运行消息和页面记录。再次发问沿用该会话上下文。

模型可读思考通过独立的 `on_thinking` 回调接收 `thinking_delta`，正文仍使用 `on_text`。Loop 发送独立思考增量，并在 `model_end` 附带最终思考文本；Web 按同一调用 ID 累积、节流推送，最终快照覆盖增量，避免重复拼接。没有思考流能力的客户端仍可通过最终响应展示可读思考。

页面记录增加 `thinking`、`thinking_status`，在原消息内以默认折叠区域显示，使用纯文本转义，单条最多展示 200,000 字符。签名、加密/遮盖思考块和工具参数不作为思考正文展示；原始响应仍按原协议保留。失败、取消和重启恢复未完成消息时标记中断。展示不增加模型请求，也不自动开启供应商的付费思考配置。

## 权限与批准

运行时的 PermissionManager 继续决定 allow/deny/ask。Web 仅提供 approver 回调，不自行放宽权限：

```text
权限模块要求批准
→ Web 回调建立唯一申请 ID
→ SSE 通知页面显示弹窗
→ 用户通过 POST 提交允许/拒绝
→ 校验申请属于此会话且仍待处理
→ 唤醒等待的执行线程
→ 权限模块设置本次标记或返回拒绝
```

停止、服务关闭、审批超时都拒绝未完成申请。重复处理、过期申请返回 409。沙箱失败不自动回退宿主机；单次提权结束仍由原 Loop 清除临时标记。

## 运行中切换权限与模型

右上角两个入口通过 `POST /api/sessions/{id}/settings` 提交权限或模型配置。`permission_mode` 为三种模式之一；升级到 `full` 必须同时传 `confirm_full: true`。模型使用 `provider` 与 `model`，只接受后端已配置的服务或 Mock，不允许网页任意指定新地址、密钥。模型 ID 在下一次实际请求时由服务验证。

HTTP 线程仅排队，不修改正在执行的 Runtime；`pending_settings` 通过 SSE 呈现。Loop 在每次模型准备前、每个工具校验前调用 `apply_controls`，由原执行线程应用新设置。当前调用完成后才切换，同一响应中的下一条工具调用也受新权限约束；如果模型直接结束，回合收尾阶段应用设置。空闲时直接应用。未生效的队列不跨服务重启恢复。

切换权限会使旧审批失效并返回拒绝，避免旧授权跨策略生效。Runtime 同步更新 PermissionManager、沙箱开关和 Bash 描述，关闭旧容器并在下次访问时按新模式创建 RW/只读挂载。不会中断已经启动的宿主机命令，也不会回滚已完成的文件修改。

`SwitchableLLM` 为 Loop、压缩器、记忆提供稳定引用；边界处替换底层客户端，因此不会出现界面显示新模型而循环仍调用旧模型的问题。保留对话、工具与累计统计，每次模型调用的诊断事件记录实际模型名称。自动目标评估跟随主模型，显式指定的评估模型保持原配置。

## 会话与恢复

存储在 `<后端 state_dir>/web/<id>/session.json`。写入使用临时文件加替换，保留元信息、运行上下文、任务清单、统计及最近 500 条页面记录。不序列化 Settings 或 API 密钥。

每次 SSE 连接先发送最新快照，因此断线重连和刷新不会重新执行任务。事件队列保留最近 2048 个事件，消费者落后时重新发送快照。原始对话仍由运行时压缩策略管理。重启时不自动重跑未完成操作，旧工具记录标记为中断。

会话默认关闭团队与长期记忆以控制第一版范围。任务执行采用现有协作式取消，正在运行的工具或模型请求不能保证立即中断。已批准的宿主机命令及其子进程具有当前系统用户权限。

## 本地边界与验证

服务绑定 `127.0.0.1`；拒绝外部 Host 和外部网页 Origin，不允许被嵌入其他页面。开发模式通过 Vite 代理。Markdown 渲染经过 DOMPurify，模型输出不会直接作为可信 HTML。

后端测试验证参数检查、单次批准后恢复容器、拒绝与取消无写入、会话恢复、事件恢复和来源拦截。浏览器测试验证真实 Mock 事件、工具记录、页面刷新、手机尺寸、新建会话错误反馈，以及拒绝按钮焦点和不可信 Markdown。没有运行付费模型请求。
