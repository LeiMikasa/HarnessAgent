# 文件工具写前读取与版本保护

`read_file`、`write_file`、`edit_file` 现在使用 Python 标准库实现的 `ObservedFiles`，参考 [DSH 的观察策略](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/fs/fs-observation-policy) 和[文件系统后端分层](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages/fs/fs-local)。这是针对 minicode 的独立实现，没有复制 TypeScript 插件或引入 DSH 运行时。

## 实际行为

| 操作 | 结果 |
|---|---|
| 直接创建不存在的文件 | 允许；成功后记录新版本 |
| 覆盖或编辑没读过的已有文件 | `FS_NOT_OBSERVED`，要求先 `read_file` |
| 读取后，文件没有变化 | 允许覆盖或编辑，成功后更新记录 |
| 读取后被用户、Bash 或其他会话改动 | `FS_STALE_VERSION`，要求重新读取 |
| 刚成功创建、覆盖或编辑后继续修改 | 允许，不需要机械地重复读取 |
| 读取后被外部删除 | 拒绝旧版本写入；重新读取确认不存在后允许创建 |
| 确认不存在后，被其他人创建 | 拒绝覆盖并保留对方文件 |
| 仅通过 glob/grep 找到文件 | 不建立可修改的观察记录 |

普通分段读取会建立版本观察；这保证版本新鲜性，不保证模型完整看过文件。已有的未知写入状态保护仍独立生效，只有完整、未截断的读取或确认不存在才能解除 `STATE_CHECK_REQUIRED`。

主 Agent 的观察记录跨同一 Runtime 的用户轮次保留。子 Agent 使用独立记录，队友记录在其自身多轮调用间保留。记录只在内存中，不随 Web 对话存档持久化；恢复或重建 Runtime 后，已有文件需要重新读取。CLI/TUI 的 `:clear` 同步清除主 Agent 的观察记录。完全权限和单次宿主机审批不跳过观察检查，文件访问权限仍先由原有权限流程决定。

## 实现

- `agent/tools/filesystem.py`：记录规范路径下的版本，组合文件身份、大小、mtime、权限位及 SHA-256 内容摘要。Windows 的 path stat 和 handle fstat 对 ctime 的语义可能不同，因此 Windows 不将 ctime 纳入版本比较。
- `agent/tools/registry.py`：每个 ToolContext 默认持有独立记录；child() 默认不继承。
- `agent/teams.py`：队友在自己的 ToolContext 之间复用记录。
- `agent/tools/basic.py`：基础文件工具接入读取和修改检查；参数和工具名称保持不变。
- `agent/tools/result.py`：`reread` 恢复说明要求重新使用 read_file 检查实际内容。

文件修改在进程共享、按规范目标路径划分的锁内执行：检查版本、准备临时文件、再次检查、发布、记录新版本。临时文件与目标位于同一目录，写完执行 flush/fsync。覆盖使用原子替换，Windows 使用 ReplaceFileW 保留目标 DACL；新建使用不可覆盖的硬链接发布，已有目标会导致失败。硬链接不可用时返回错误，不退化为可能覆盖目标的创建方式。正常清理只删除当前调用独占创建的临时文件。

临时文件准备失败时保留原目标；发布阶段失败保守标记副作用未知，并忘记观察记录，要求读取后恢复。文件编辑沿用唯一文本匹配和 replace_all 规则，并保留占主导的 CRLF 换行。

## 边界

这些检查覆盖已注册的三个文件工具。Bash、MCP 或其他进程的直接文件操作不经过观察策略；后续文件工具修改会核对实际版本。工具选择禁令仍依赖提示词，不是 Shell 命令解析拦截。

同一进程通过这些工具进行的写入由共享锁串行化。外部进程不持有该锁；写入前的再次检查能发现准备阶段的修改，但检查和原子替换之间仍有外部写入竞争窗口，不能声称跨进程的完整 compare-and-swap。新建的硬链接发布则保证不覆盖已经出现的目标。

## 验证

`tests/test_file_observations.py` 覆盖未读拒绝、读后修改、连续编辑、内容变化、删除后重建、并发创建、分段读取、上下文隔离、路径别名、并发会话、写入故障、CRLF 和 Windows DACL 保留。真实 Docker 挂载互通继续使用 `verify_file_tools_sandbox.py` 验证。
