# 工具错误恢复

本次升级适用于统一 Agent Loop，主 Agent、子 Agent 和队友各自持有本轮恢复状态。没有调用付费模型验证效果；离线故障测试验证机制，真实任务效果需要另做对照。

## 执行流程

收到工具请求 → 检查恢复预算 → JSON Schema 校验 → 权限 Hook → 执行 → 按错误类型决定有限重试或反馈模型。

`ToolRegistry.validate()` 使用 jsonschema 检查必填字段、类型、嵌套约束及 Schema 规定的范围。六个基础工具拒绝额外参数；外部工具按其 Schema 的约束校验。校验不转换模型参数，不远程下载 `$ref`，参数不合法时不执行权限审批和工具处理函数。

## 错误结果

`ToolResult` 保持 Python 字符串接口兼容，但错误元数据独立于文本；框架不会猜测以 `Error:` 开头的日志是否失败。错误回传模型时转为 JSON，并设置 `is_error=true`：

```json
{
  "ok": false,
  "error_code": "INVALID_ARGUMENT",
  "message": "Error: 123 is not of type 'string'",
  "field": "content",
  "auto_retry": false,
  "next_action": "correct_arguments",
  "execution_status": "not_executed"
}
```

实际反馈还包含 `recovery_hint`。`auto_retry=false` 表示反馈已经交给模型，框架不会继续自动重试这次调用；内部尝试的重试决策见 `tool_attempts`。

新增处理函数应明确返回 `ToolResult.failure()` 或抛出 `ToolError`。普通文本仍作为成功结果，不依赖文本前缀判错。

## 恢复策略

| 错误 | 处理 |
| --- | --- |
| INVALID_ARGUMENT / UNKNOWN_TOOL | 反馈字段、规则或可用工具，由模型修正 |
| NOT_FOUND / PRECONDITION_FAILED | 提示读取或查找真实信息后修正 |
| 明确的暂时性故障 | 仅 read_only 与 retry_safe 均为真的工具可自动重试 |
| PERMISSION_DENIED / POLICY_BLOCKED | 不自动重试，不绕过权限 |
| 未分类异常、MCP isError 业务失败 | 不自动重试，保留失败与执行状态 |
| 文件修改结果 unknown | 标记目标不确定，再次 write_file / edit_file 前要求完整检查 |

只读重试最多执行三次，包含首次调用。两次等待使用带随机抖动的指数退避，上限分别为 0.25 秒和 0.5 秒。每次尝试重新经过权限 Hook，一次性越界授权在尝试结束后清除。自动重试不额外调用大模型，但会消耗工具执行时间。工具自身存在重试时，要避免重复叠加预算。

基础 read_file、glob、grep 由宿主允许只读重试。MCP 仅宿主 `retry_safe_tools` 名单中的工具启用；当前 Runtime 默认允许 docs/search、docs/get_version、docs/list_topics。服务器 annotations 不构成授权。bash、文件写入、修改、任务调度和部署默认不自动重试。

## 模型修正预算与状态检查

同一循环中，按调用者、工作区、工具名和操作目标记录可修复错误。文件目标使用规范化绝对路径。首次失败后给模型两次修正机会，连续失败三次后，后续调用在执行前返回 RECOVERY_EXHAUSTED。更换失败参数不会自动重置同一目标的计数；该工具对该目标成功执行后重置。其他工具的成功不会清除它。新的循环使用新的预算，总循环轮数上限仍有效。

write_file / edit_file 的异常若导致结果 unknown，本轮对同一文件的两种修改都被 STATE_CHECK_REQUIRED 拦截。read_file 完整读取且没有输出截断，或通过实际文件状态检查确认文件不存在，才解除状态检查门槛。无法读取、读另一个文件、部分读取或截断预览都不算。读取证明已经提供状态供模型检查，不代表自动证明原写入正确，也不会消耗或重置修改参数修复预算。

当前门槛是循环内的保守控制，不是持久化幂等或事务机制。超大文件超过 read_file 输出限制时，不会通过部分读取自动解除门槛。bash 的任意副作用无法通用验证，框架不自动重试并反馈检查实际状态的提示。一次性 Runtime.execute_tool 调用没有跨调用修复预算，预算保护由 run_loop 持有。

## 记录与验证

每轮的 `ToolContext.extra["tool_attempts"]` 记录工具名、参数哈希、处理阶段、尝试序号、错误码、执行状态、耗时及是否自动重试。只记录参数哈希，不保存参数原文。`evals.recall50` 将该列表保存到每次运行的 result.json。

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_tool_recovery.py'
.\.venv\Scripts\python.exe -m unittest discover -s tests -p 'test_*.py'
```

测试覆盖校验阻止副作用、共享修复预算、正常修复、暂时故障恢复、重试耗尽、权限拒绝、写后超时不重放、状态检查门槛、MCP 业务错误及不信任服务端只读声明等情况。Mock 不证明真实模型一定会按照恢复提示做出正确决策。
